阿里云RAM用户、角色、权限
2026-05-20 19:28:25

RAM 用户就是主账户创建的，理解为老板和员工，老板(主账户)肯定不能干活吧、所以把工作全部分配给员工(ram 用户)，老板给每个员工分配权限
a 管理 oss
b 管理云主机
c 管理数据库
当某个业务出现问题可快速定位，归根结底为安全，主账户相可以理解为 root 了，直接操作风险很大，比如 AK/SK 泄露，RAM 用户 AK/SK 泄露也只能接管一些权限，角色 TST 泄露是限时的，随着权限细分危害一点点减少

通过 RAM 的 AK/SK 生成 STS，当你给 RAM 用户授权只读，不代表使用 ram 用户创建的角色就只能比只读权限还低，听起来不太符合逻辑，下属比上级权限还高？

当角色被创建时，决定它权限的不是 ram 用户而是策略，可以理解为父与子，同时又是两个独立个体，子可以比父更优秀
